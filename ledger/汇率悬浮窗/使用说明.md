# 梦幻西游汇率悬浮窗 · 使用说明

一个常驻桌面的白色小窗：**平时完全透明、看不见，鼠标移上去才显形**。显示你所在区服（**白云山 · 广东4区**）的梦幻币行情，每天在 **0 点 / 8 点 / 12 点 / 18 点 / 22 点** 各刷新一次，并画出近 7 日价格曲线。

## 屏幕上显示什么

| 行 | 含义 |
|---|---|
| 白云山 · 广东4区 | 区服 |
| **1 元 ≈ 13.3923 万** | 现在 1 元人民币能换到多少万梦幻币（主行情，保留四位小数） |
| 1 万梦幻币 ≈ ¥0.0747 | 反过来：每 1 万梦幻币值多少人民币 |
| 金价 ¥224.01/3000万 ↑+1.00 · 7日 -4.4% | 原始金价（元 / 3000 万），以及较昨日、近 7 日涨跌 |
| 近 7 日走势（228.5 → 224.0，-2.0%） | 曲线标题：一周起止价与累计涨跌幅 |
| 曲线 | 近 7 日每日收盘价，末点标「现 x.x」 |
| 采集 10-31 10:40 · 下次 18:00 刷新 | 行情采集时间 + 下次刷新时刻 |

窗口已**去掉当日曲线**，只保留一周趋势；当天价格靠悬浮窗自身的刷新与历史记录，不进曲线。

## 怎么操作

- **拖动**：按住窗口任意位置拖动，位置会被记住，下次启动回到原位。
- **贴边收起**：把窗口拖到**屏幕上边**或**屏幕右边**松手，窗口自动缩成一条 **28×150 的竖直绿胶囊**（绿底白字），竖排显示「1元 ≈ 13.3923万」（保留四位小数，用 ≈ 符号，不写「约等于」），贴着屏幕边沿，不挡视线。
- **展开**：单击小胶囊即恢复完整窗口（会自动离开边缘一点，避免又被收起）。
- **⟳ 小按钮**：右上角，点一下立即重新取数（不影响 0/8/12/18/22 的固定计划）。
- **右键**：立即刷新 / 复制当前汇率 / 切换置顶 / 退出。
- **右上角 ✕**：关闭（双击桌面/启动项里的启动器可再开）。
- 窗口默认置顶，不会被游戏或浏览器盖住。

## 外观

- 白色玻璃，**常态 25% 不透明**：只有一层淡影，能看见轮廓但不挡画面，也不是黑背景。
- **鼠标移到窗口上**（不用点）立刻变成 **完全不透明（100%）**，读数清楚；鼠标移开变回 25%。
- 常态下窗口正常接收鼠标（不穿透），要拖动就先移上去让它显形；只有把常态调到 0（完全看不见）时程序才会自动开启鼠标穿透。
- 启动后先亮 **3 秒**，让你确认窗口在哪。
- 收起成绿胶囊时同样规则：常态 25% 淡影，悬停 100% 实心，单击展开；两端是圆角，靠边像贴了一个标签。
- 展开态描边浅灰 `#D5DBE4`；胶囊态不加描边，避免绿底上出现灰线。
- 想改常态深浅：源码里 `$script:BaseOpa = 0.25`（0 = 全透明隐形，1 = 完全不透明）；悬停实心程度看 `$script:HoverOpa = 1.0`。

## 数据从哪来

- 最新价：阿鱼工具箱公开行情 `/api/prices/latest`（一次返回全部区服，程序只取 `广东4区 / 白云山`）。
- 近 7 日：同站 `/api/prices/history?group=over3&source_id=85`，日线，取最后 7 个点。
- 口径：`price` 是「元 / 3000 万梦幻币」，程序自己换算成「1 元 ≈ 多少万」和「1 万 ≈ 多少钱」。
- **不是网易官方汇率**，是第三方每日采集的市场快照，实际成交以藏宝阁为准。
- 该接口**没有小时级/当日走势**（hour、5m、intraday 等粒度一律 422），所以当天价格只能靠本机每次刷新的记录，这也是取消「当日曲线」的原因。

## 刷新节奏

- 启动时立刻查一次；
- 之后固定在 0:00 / 8:00 / 12:00 / 18:00 / 22:00 五个时刻各查一次（到点查完自动排下一次）；
- 网络失败重试 3 次，仍失败就保留上次价格，底部红字提示「取数异常，保留上次」，不会显示成空窗。

## 面板底部的在售概要

面板高度 276 → 336 → **380 起，再按「在售明细」行数自动加高**，底部两组概要（中间各有一条浅色分隔线）：

**第一组：在售快照**

- 第一行：`在售快照 10-31 15:54 · N 款 · M 件`（记录时间 = 最新一次盘点或补货的时刻）
- 件数口径：**最新一次盘点 = 基数**，此后每次补货都在这份基数上累加；到下一次盘点整组覆盖，重新当基数
- 第二行：`金币合计 X 万 ≈ ¥Y`（金币按各款【执行单价 × 件数】累加；人民币按**当前**行情实时折算，行情一变数字跟着变，不写死）
- 再往下按等级列明细，一条一级、同类顺序固定为 **戒指 → 耳饰 → 手镯 → 佩饰**，缺哪类跳过：

  ```
  60级：香木镯 6 + 芝兰佩 4
  80级：芙蓉戒 5 + 明月珰 3 + 翡玉镯 5 + 逸云佩 9
  100级：金麟绕 5 + 玉蝶翩 5 + 墨影扣 7 + 莲音玦 5
  120级：悦碧水 3 + 点星芒 2
  ```

  一行放不下时自动折行，行首缩进对齐到冒号后；没有在售款时这段不占高度。
- 还没统计过时显示：`在售快照：尚未统计（发摆摊/背包截图给我）`

**第二组：当日日结**

- 这一组右侧有两个小按钮，用来切「今日 / 昨日」两种视图（选中的是蓝色，未选中是浅灰）
- **今日**：
  - 第一行：`10-31 · 期初 59 件 · 补货 0 次`
  - 第二行：`销量 37 件 · 41,300 万 ≈ ¥3,083.9`（蓝色）；期末盘点还没到时显示灰色的 `销量：待次日 0 点盘点后生成`
  - 第三行只在当天做过中途核对时才出现（橙色）：`即时 21:05 已销 8 件 · 3,160 万 ≈ ¥236.0`
- **昨日**：显示前一天已经日结的那一组数字（`10-30 · 期初 … 件 · 补货 … 次` + `销量 … 件 · … 万 ≈ ¥…`），前一天还没结完则显示 `昨日未日结（缺期末盘点）`；昨日视图不显示即时行，面板会自动缩回一行高度
- 今日数据来自 `today.json`，昨日数据来自 `yesterday.json`，两者都由 `每日盘点\日结.py` 在结算时写出，点 ⟳ 就重读。

数据来自 `%APPDATA%\MHXY-RateWidget\stock.json`，结构：

```
{
  "updated_at": "2026-10-31T11:20:00",
  "items": [
    { "code": "ring_140", "name": "九曜光华", "qty": 2, "unit_price_wan": 3300 },
    { "code": "ear_140",  "name": "凤羽流苏", "qty": 1, "unit_price_wan": 2800 }
  ]
}
```

- `qty` 只统计大于 0 的款；`unit_price_wan` 为空的款只计件数不计金币（对应 160 级四款待报价）。
- 点 ⟳ 或右键「立即刷新」会重读这个文件，改完立刻生效，不用重启。

## 每日盘点 / 补货 / 日结流程

**核心约定：每天只有一张表** —— `每日盘点\YYYY-MM-DD.csv`，上半是当天明细，下半（空一行后）是同一张表里的汇总区，不再另外生成汇总文件。

1. **每天 0 点后**：你发行囊（或摊位）截图，这是对**前一天**的盘点结存，我逐格统计成「盘点」行记进当天文件，并同步刷新面板第一组的 `在售快照`。
2. **早上 7 点起**：每次补货你发截图，我按**新增增量**记「补货」行，登记 **时间 + 款 + 数量**（同一天可多次，逐次累加）。
3. **次日 0 点**：你再发盘点截图，我把这组记成当天的「期末」。
4. 只要期初和期末都在，`日结.py` 立刻算出：**当日销量 = 期初 + 补货 − 期末**（按款），**销售额 = Σ(销量 × 当日执行单价)**，按当天汇率折人民币，把汇总区写回**同一张表**，同时刷新面板第二组。
5. 只统计灵饰，旗子 / 挂牌 / 宝盒 / 卷轴这类杂物一律不计。

**中途核对（每天 10:00–22:00）**

你白天发一张截图说"统计一下现在还剩多少"，我按「核对」处理，规则是**只读不改**：

- 拿这次数出来的件数，跟当时的应有数（盘点基数 + 已补货件数）比对，差额就是**即时销量**
- 即时销售额 = Σ(即时销量 × 执行单价)，按当前汇率折人民币
- 面板第三行出橙色一行：`即时 21:05 已销 8 件 · 3,160 万 ≈ ¥236.0`
- **在售快照、在售明细、基数一律不动**；核对行只在当天表里留一条「核对」记录备查
- 白天核对不影响次日 0 点的正式日结，正式销量仍以两次盘点为准

明细区列含义：

| 列 | 说明 |
|---|---|
| 日期 / 时间 | 截图对应的营业日 + 我登记的时刻 |
| 类型 | `盘点`（0 点结存）或 `补货`（白天补货）或 `核对`（白天临时盘点，只算即时销量） |
| 款号 / 类型名 / 等级 / 名称 | 例如 `brace_100` / 手镯 / 100 / 墨影扣 |
| 数量 | 该款在本次盘点（存量）或本次补货（新增量）的件数 |
| 执行单价(万) / 金额(万) | 当日执行单价与 `单价×数量` |

汇总区（表的下半段，两列 `项目 / 值`）：

| 项目 | 说明 |
|---|---|
| 状态 | `已日结` 或 `待次日盘点` |
| 期初件数 / 期末件数 | 当天首末两次盘点的合计件数 |
| 补货次数 / 补货件数 | 当天补货截图张数与新增总件数 |
| 销量件数 | 期初 + 补货 − 期末 |
| 销售额(万) / 折人民币(元) | 按当日执行单价与当日汇率折算 |
| 汇率(元/3000万) | 结算时用的金价 |
| 备注 | 未报价款、销量为负待确认等 |

手动重算某一天：`python "梦幻西游灵饰\每日盘点\日结.py" 2026-10-31`（不传日期则算最新一天）。重跑只覆盖汇总区，明细不动。

## 月度销售统计（看哪款好卖）

跑一个月之后，用 `月报.py` 把整月的日表汇总成一份月报：

```powershell
python "C:\Users\wangwill\Doubao\chats\2026-10-31\new-chat\梦幻西游灵饰\每日盘点\月报.py" 2026-11
```

- 不传月份就取目录里最新月份；产出 `每日盘点\月报-2026-11.csv`，同时在屏幕上打一段摘要
- 三个区：**月度经营汇总**（月销量、销售额、折人民币、日均、补货次数、动销款数）、**按款排名**（销量、销售额、占比、动销天数、动销日均）、**按日明细**（每天期初/补货/期末/销量）
- 口径跟日结完全一致（直接复用 `日结.py` 的算法）：每天销量 = 首次盘点 + 补货 − 末次盘点，只计灵饰，只计已日结的日子；未日结的日子列出但不进合计
- 中途「核对」行不进月报，避免半天的临时数被当成销量
- 折人民币按**当天**的汇率逐日算，历史价格波动不会被今天的汇率带偏

## 常见问题

- **数字不更新**：先点 ⟳ 或右键「立即刷新」；仍不动就查 `history.jsonl` 最后一条的 `ts` 和 `ok`，`ok:false` 表示当时网络/接口异常。
- **窗口太淡看不清**：常态是 25% 淡影，鼠标移上去立刻变成完全不透明；想常态就更清楚就改 `$script:BaseOpa`（如 0.45）。
- **窗口变成绿胶囊了**：单击胶囊展开；想让它不再自动收起，就往屏幕中间拖，别贴边松手。
- **想换区服**：改 `widget.ps1` 顶部的 `$script:Region` / `$script:Server` 两行（历史接口的 `$script:SourceId` 也要换成对应区的 id），重启悬浮窗。
- **窗口位置丢了**：删掉 `state.json` 再启动即回到默认位置。
