## 二、已验证的开发死路（踩了必崩）
1. **sqlite动态加载必须显式标`__cdecl`调用约定**：所有导出函数指针必须写成`typedef int (__cdecl *xxx)(...)`，漏写会栈不平衡，启动直接0xC0000005内存访问错误闪退
2. **扫码枪回车不能放在主窗口WM_KEYDOWN**：EDIT控件会吞掉回车消息，主窗口永远收不到，必须给扫码框子类化（SetWindowLongPtrW改WndProc），截获扫码框自己的WM_KEYDOWN回车事件
3. **GDI和Static控件不能同时画同一区域**：会导致文字叠字，列头/行标题统一用Static控件写，网格线/数字统一用GDI画
4. **编译前必须先杀进程**：否则链接时提示"无法打开输出文件 拒绝访问"，exe被正在运行的进程占用
5. **浏览器访问localhost会被HSTS缓存强制升级为HTTPS**：固定用8000端口，桌面快捷方式直接指向`http://localhost:8000`，不要手动在地址栏输localhost，避免自动加s导致连接被拒
6. **网页版单线程服务会一错全崩**：必须用`ThreadingHTTPServer`多线程模式，单请求出错不影响整体服务
7. **bat启动脚本三个必崩坑**（2026-11-18 实测）：
   - Python路径不能写Doubao沙箱runtime的哈希目录（如`.../sandbox_runtime/bases/772984f6.../pythonw.exe`），该哈希每次运行会变，路径直接失效；必须写死全局Python绝对路径：`C:\Users\wangwill\AppData\Local\Programs\Python\Python312\pythonw.exe`
   - bat文件必须存为**GBK(936)编码 + CRLF换行**；UTF-8无BOM或LF换行都会被cmd错误解析（中文路径乱码、每行首字母被吞、`cd`找不到目录）
   - 脚本开头必须`chcp 936 >nul`固定代码页，否则GBK中文路径被按UTF-8解码成乱码；延时用`ping 127.0.0.1 -n N >nul`替代`timeout`（后者在非交互重定向环境直接报错退出）
8. **服务调子进程禁止用裸`python`，必须用解释器绝对路径**（2026-11-19 实测）：后台常驻服务进程启动时冻结PATH，裸`python`会被解析到Doubao沙箱runtime哈希目录（`.../sandbox_runtime/bases/<哈希>/python/python.EXE`）；该哈希目录随环境变化/失效后，旧常驻进程再调子进程启动失败、无任何输出，后端解析空串报错，前端弹"扫码解析失败"。`server.py`里`subprocess.run`必须传`sys.executable`（服务自身Python312解释器绝对路径），不依赖PATH；同理脚本、bat、快捷方式都不得写沙箱哈希目录路径

## 四、二维码解析规则（43位固定长度）
格式：`MMDDHHMMSS`(10位时间戳) + `操作符`(1位I/O/C/E) + 32位数量段（每2位对应一个品类数量，共16个品类）
1. I=入库：对应品类库存+N
2. O=上架：对应品类库存-N、在售+N
3. C=中途盘点：对比上一次盘点值，差额=期间卖出，写销售明细，在售矩阵覆盖为盘点值
4. E=日结盘点：当天最后一笔，E之后所有操作自动归第二天，触发当日总销售汇总

## 五、当前网页版工作台功能清单（2026-11-16最终版）
### 1. 顶部看板
- 四个核心指标卡片，从左到右顺序：**在售总件数 → 库存总件数 → 今日已售 → 今日已回款**
- 点任意卡片弹窗显示对应明细：在售4×4矩阵、库存4×4矩阵、今日分品类销售、当日逐笔回款记录
- 顶部右侧按钮组：价格管理、日报/周报、手动刷新，全部靠右排列
### 2. 扫码待处理审核机制
- 扫码枪扫入43位二维码，解析后**不直接改库存/在售**，直接写入`pending_scan`表
- 待处理记录持久化在后端数据库，刷新页面、关闭浏览器都不丢失，支持跨小时事后审核
- 流水列表里待处理单为黄色背景，带「确认入账」「撤销」按钮，确认后才真正改库存/写销售明细，撤销则从待处理表删除
### 3. 扫码流水列表
- 主区域整块为今日流水列表，三色状态区分：
  - 🟡 黄色：待处理单据（带操作按钮）
  - 🟢 绿色：已入账记录
  - 🔵 蓝色：自动生成的信息汇总条
- 自动汇总规则：
  1. C中途盘点确认后，自动插入蓝色条：本轮盘点卖出件数/金额
  2. E日结确认后，自动插入两条蓝色条：本次E盘点销售情况 + 当日全天总销售汇总
- 流水底部固定显示昨日日结汇总卡片：由后端`/data`的`yesterday`字段按最近一次E日结动态返回（日期/销售件数金额/回款/盘点在售件数），前端只读接口数据，**禁止在HTML里写死历史数字**；当天无历史日结时卡片自动隐藏
- 所有历史流水记录永久保留，不自动清理
### 4. 辅助功能
- **回款登记**：输入框缩短，按钮紧跟输入框同一行，超过当日销售额自动记为点卡/预收
- **价格管理**：弹窗编辑全品类成本价、售价，带密码校验（密码`admin`），自动计算毛利率
- **日报/周报报表**：
  - 当日日报：销售件数/金额、回款、毛利润、综合毛利率，16个品类全量列出（0销量也显示），严格按固定顺序排列
  - 近7天周报：累计销售、回款、毛利润、每日日销售明细
  - 回款超销售额时自动显示「多回款X万」，不显示负数未回款
- 所有弹窗右上角固定黑色圆形×关闭按钮
### 5. 服务稳定性
- 多线程`ThreadingHTTPServer`，单请求出错不崩溃
- 桌面提供`启动灵饰工作台.bat`脚本：先按8000端口杀掉旧进程→用全局Python 3.12的pythonw后台起`server.py`→固定调用Chrome打开`http://localhost:8000`；同构脚本共4份：桌面`启动灵饰工作台.bat`、项目内`启动工作台.bat`/`重启服务.bat`/`打开工作台.bat`，均为GBK+CRLF编码
- 桌面快捷方式「灵饰经营工作台」直接打开`http://localhost:8000`，避免手动输入被浏览器HSTS自动加s
- 桌面「灵饰经营报表」文件夹存放自动生成的md日报，生成脚本`gen_daily_report.py`
