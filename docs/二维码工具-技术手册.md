## 一、软件概述

**入库上架二维码打印工具** 是一个面向《梦幻西游》摆摊商人（灵饰品类）的桌面小工具，用于把 16 个灵饰格子的入库 / 上架数量编码为二维码，并打印到 58mm / 80mm 热敏小票上，同时自动把整页单据保存为 PNG 留档。

- 交付形态：**Win32 C++ 单 EXE**（无需安装、无依赖，绿色分发）
- 主窗口类名：`MhxyQrToolWnd`；帮助窗口类名：`MhxyQrHelpWnd`
- 窗口尺寸：**626 × 429**（客户区 620 × 400）
- 界面语言：简体中文

### 核心功能

| 功能 | 说明 |
|---|---|
| 入库 / 上架 / 盘点切换 | 系统选项卡「入 库」「上 架」「盘 点」（文字居中、无括号字母），切换即时刷新合计与二维码数据 |
| 数量录入 | 16 格输入框（0~99，仅半角数字）+ 每格 ▲/▼ 步进按钮 |
| 二维码生成 | 按数据契约实时编码（界面不显示预览，仅供打印/存档） |
| 打印 | 系统打印对话框选择打印机，58mm/80mm 自适应排版，打印成功自动清空 |
| 自动存档 | 打印时按数据签名查重，未保存过的数据静默存整页 PNG 到「保存单据」文件夹 |
| 数量合计 | 按当前选项卡显示「入库合计 / 上架合计 / 盘点合计 N 件」 |
| 入库并同时上架 | 复选框（仅入库时显示）：勾选后一次打印/存档入库 + 上架双份 |
| 盘点票（C/E） | 「盘 点」标签：默认中途盘点 C，勾选「日结盘点(E)」复选框为 E；16 格填**实际在售件数**快照 |
| 防误操作 | 入库/上架全零禁用按钮、失焦 5 分钟自动清空、打印成功自动清空；**盘点票允许全零，但全零打印须二次确认（默认「否」）** |
| 帮助 | 非模态「操作指南」窗口，按钮行最右「帮助」 |

## 四、编译与构建

### 4.1 主程序

工具链全部在 `toolchain\w64devkit\w64devkit\bin\` 下。

```powershell
# 1) 编译资源（先停掉正在运行的旧实例，否则 ld 报 Permission denied）
Stop-Process -Name "入库上架二维码工具" -ErrorAction SilentlyContinue

# 2) 资源编译
& .\toolchain\w64devkit\w64devkit\bin\windres.exe src\app.rc -O coff -o src\app_res.o

# 3) 主程序编译链接
& .\toolchain\w64devkit\w64devkit\bin\g++.exe -O2 -municode -mwindows -std=c++17 -DNDEBUG `
  -finput-charset=UTF-8 -fexec-charset=UTF-8 `
  -I third_party\qrcodegen -I src `
  src\main.cpp third_party\qrcodegen\qrcodegen.cpp src\app_res.o `
  -o dist\入库上架二维码工具.exe `
  -lgdiplus -lgdi32 -luser32 -lcomdlg32 -lwinspool -lcomctl32
```

要点：
- **EXE 名不含“打印”**（文件名为「入库上架二维码工具.exe」，与产品名一致）；
- 源码 UTF-8（`-finput-charset=UTF-8 -fexec-charset=UTF-8`）；
- `-municode` → 入口为 `wWinMain`；`-mwindows` → 无控制台。

## 五、数据契约（二维码内容格式）【勿改】

二维码原文为**纯数字 + 单字符操作码**的 ASCII 串，无任何分隔符：

```
[时间戳 10 位] [操作码 1 位] [16 组 × 2 位数字，直接相连]
```

| 段 | 长度 | 说明 |
|---|---|---|
| 时间戳 | 10 位 | `MMDDHHMMSS`（月日时分秒，**不含年份**——二维码临时用，系统自动保存图片留档） |
| 操作码 | 1 位 | `I` = 入库，`O` = 上架，`C` = 中途盘点，`E` = 日结盘点 |
| 16 组数量 | 32 位 | 行序读取（60级 4 格 → 80级 → 100级 → 120级）；空框补 `00`，一位数前补 `0`，范围 00~99 |

**取值硬规则（2026-11-09 定）**：两位数规则是「≥10 原样两位，只有一位才补前导 0」，**不是**给所有数加前导零——若一律不补零，5 件会输出单字符、全串长度在 37~43 之间浮动，43 字符契约当场作废。补零规则必须保持。

**空框必须按空处理**：读格子文字时 `wchar_t buf[N]` 必须清零。`GetWindowTextW` 在文本为空时**一个字符都不写**，未初始化缓冲会把栈上残留当成内容读出来——表现为空格子随机变成 `03/05/06` 等，二维码后半段全是垃圾（`WideCharToMultiByte` 再把这些垃圾按 ANSI 转换）。修复前实测：填入前 4 格 = 10、其余 12 格留空，二维码内容竟是 `…10101010050505030106040005050505`，合计从 40 虚增到 89。

示例（60级第一格 3、其余 00，入库）：
`1103143025I03000000000000000000000000000000`

**数据签名**（防重复保存判定口径）：`操作码 + 16 组两位数字`（**不含时间戳**）。

### 5.1 盘点票（C/E）语义

| 操作码 | 含义 | 16 格填什么 | 业务用途 |
|---|---|---|---|
| `C` | 中途盘点 | **实际在售件数**（快照） | 营业中截断：营业中调价前盘一次，得出截止此时的销售，后续按新价销售记录 |
| `E` | 日结盘点 | **实际在售件数**（快照） | 收盘日结：得出当日销售，把在售与库存结转到次日 |

- C/E 都是**快照**，不是变动量（与 I/O 的±N 语义不同）；
- **允许 16 格全零**（货可能真的卖空），但打印时必弹「全零盘点票确认」，默认按钮为「否」，选否不打印也不存档；
- 盘点票不参与「入库并同时上架」双份逻辑；
- 防重签名同样适用（`C...` / `E...` 与 I/O 互不干扰），但 C/E 的业务落表尚未实施。

实现函数：
- `FormatTimeNow()` — 10 位时间戳
- `BuildContentFor(op)` — 组装完整内容
- `DataSignature(op)` — 数据签名

> 变更本契约时，必须同步 `src\main.cpp` 与 `src\test_print.cpp`、`src\test_save.cpp`（离线回归内嵌串 `1103143025I0303...`，43 字符；`qr size=25` 是去年份生效标志）。

## 六、打印与存档机制

### 6.1 打印流程（PrintQr）

```
点「打印」
 ├─ g_qr 无效 → 提示"当前没有可打印的二维码"
 ├─ 盘点票（C/E）且 16 格全零 → 弹「全零盘点票确认」（MB_YESNO|MB_ICONWARNING|MB_DEFBUTTON2）
 │    ├─ 选「否」（默认）→ 直接返回：不打印、不存档、不置零
 │    └─ 选「是」→ 继续走下面流程
 ├─ dual = (当前为入库 && 勾选"入库并同时上架") → 再编码一份上架二维码 q2
 ├─ ensureSaved(当前操作)  [+ q2ok 则 ensureSaved('O')]
 │    └─ 按 DataSignature 查 g_savedSigs：未存过 → 静默存整页 PNG 到「保存单据」
 ├─ PrintDlgW(PD_RETURNDC|PD_USEDEVMODECOPIESANDCOLLATE)
 │    ├─ 取消（!got）→ 返回，不置零
 │    └─ 确定 → StartDoc/StartPage/PrintPage ×1~2 → EndDoc → DoReset()  // 打印成功自动清空
 └─ 打印对话框打开期间 g_inDialog=true（暂停失焦计时；全零确认弹窗期间同样置 true）
```

- 打印页渲染见 `print_page.hpp`（见第七章）；
- **打印内容在点击「打印」的瞬间按当前 16 格现算**（`PrintQr` 开头 `BuildContentFor(CurrentOp())` + `EncodeQrInto`，存档的 `ensureSaved` 同样现算），**不读 `g_content`/`g_qr` 缓存**。缓存只在 `UpdatePreview` 里随 `EncodeQrInto` 成功而更新，一旦某次刷新没走到或编码失败，缓存就会停在旧内容，打印出来的码和界面上填的数字对不上、存档名也跟着错（2026-11-09 二次加固）；
- 打印期间自动存档的文件名：`操作_时间戳_数字串.png`（全角逗号换下划线，UTF-8 转 UTF-16）；
- 相同数据重复打印会因时间戳不同生成多张 PNG——这是"打印成功之后重置"设计的既定行为，已获用户接受；
- 打印作业提交成功后 `DoReset`，其中**显式调用一次 `UpdateTotalLabel`**：置零后合计必须归 0，不能留着上一批的 40/89。

### 6.2 存档目录与命名

- 目录：EXE 同目录 `保存单据\`（不存在自动创建）
- 文件名：`入库_1103143025_0300000000...png`（`OpName_时间戳_数字串`）
  - 切片口径必须按 **10 位时间 + 1 位操作码**：`c.substr(0,10)` / `OpName(c[10])` / `c.substr(11)`；
  - 2026-11-09 修：原先仍按旧的「14 位时间」契约切片（`substr(0,14)` / `c[14]` / `substr(15)`），导致 `c[14]` 取到的是数量段首位、`OpName` 落空，**所有存档名的操作名都变成「日结盘点」**，与真实操作码无关；
  - 长度不足 11 直接返回 `未命名.png`，不越界取字符。
- 盘点票对应 `中途盘点_…png` / `日结盘点_…png`（`OpName` 四态：入库/上架/中途盘点/日结盘点）
- 保存格式：整页 80mm 版白底位图 **639×959 @203dpi**，与打印页同源渲染

### 6.3 已保存签名集合

`g_savedSigs`：本次运行内已保存过的 `DataSignature` 列表。`SavePageToFile` 成功即入集合；`ensureSaved` 命中集合则跳过（避免打印时重复补存同一批数据）。

## 七、打印页渲染规格（print_page.hpp）【定稿勿动】

单页排版自上而下：

```
┌─────────────────────────────┐
│       入 库 明 细            │  ← 6mm 粗体居中，字间一个空格位
│   （标题四态：入库明细 / 上架明细 / 中途盘点 / 日结盘点）
│ ═══════════════════════════ │  ← 双线（0.35mm）
│ 级别   戒   耳   手   佩     │  ← 表头 3.2mm 粗体
│ ─────────────────────────── │
│ 60级    0    0    0    0    │  ← 数据行 ×4（行高 5.8mm）
│ 80级   …                    │     每行后一条单线
│ 100级  …                    │
│ 120级  …                    │
│ ─────────────────────────── │
│          [二维码]            │  ← 居中，见下方比例
│     打印时间：2026-11-04 21:34 │
└─────────────────────────────┘
```

- 纸张宽度自适应：`availWmm = pageW × 25.4 / dpiX`，左右边距 4mm；
- **二维码占比 `qrRatio`**：`tabW < 60mm ? 0.96 : 0.72`
  - 58mm 热敏纸：`qrRatio = 0.96`（实测 463×799px，放大后可扫——此前 0.90 曾扫不出，0.96 用户确认更稳）；
  - 80mm 纸：`qrRatio = 0.72`（639×959px，紧凑）；
- 二维码位图：`MakeQrBitmapFor(qr, 8)`（模块 8px + 静区 `QUIET_ZONE=4`），`StretchBlt` 缩放到目标尺寸；
- **编码模式（决定能不能扫出来）**：43 位全部落在 QR「字母数字模式」字符集内（0-9 与 I/O/C/E），`EncodeQrInto` 必须走
  `QrSegment::makeAlphanumeric(content.c_str())` + `QrCode::encodeSegments({seg}, Ecc::MEDIUM, 1, 40, -1, **false**)`，
  **不要用 `encodeText`（字节模式）**。实测同一张 `13/11/10/10` 的票：字节模式 41×41 模块、单模块约 7.8px，**图像解码器都识别不出**；
  字母数字模式 29×29 模块、单模块 11px，43 位全对。`boostEcl` 必须传 `false`——提升纠错等级会把版本重新顶上去、模块又变小。
  内容万一含字母数字模式之外的字符，catch 后回退 `encodeText`。
- 打印时间：`YYYY-MM-DD HH:MM`（含年份，仅打印页）。

### 8.3 关键消息处理

| 消息 | 处理 |
|---|---|
| WM_NOTIFY (TCN_SELCHANGE) | **只 PostMessage(WM_APP_TABCHANGED)**，不在通知栈内改控件（见 12 章经验）；延后消息里读 `TabCtrl_GetCurSel` → g_radioSel → `UpdateChkVisibility()` → UpdatePreview |
| WM_APP_TABCHANGED | 标签切换延后处理：入库→显示「入库并同时上架」，上架→两个都隐藏，盘点→显示「日结盘点(E)」 |
| WM_COMMAND (BN_CLICKED) | 复选框：`g_bothChecked / g_eodChecked = (BM_GETCHECK == BST_CHECKED)`（同步式，非取反）；勾选 E 后立即 UpdatePreview（操作码 C→E 变化）；步进钮：SpinEdit ±1 |
| WM_COMMAND (EN_CHANGE) | 16 输入框 → UpdatePreview |
| WM_DRAWITEM | 仅自绘 ▲/▼ 步进钮（蓝色系 50,90,150）；复选框/命令按钮由系统绘制 |
| 命令按钮字体 | `g_btnFont = CreateFontW(-15, FW_BOLD, 微软雅黑)` + 每按钮 `WM_SETFONT`；**主题化按钮会忽略 WM_SETFONT**（WM_GETFONT 回读=Microsoft YaHei UI 400），用户已接受现状，勿再改自绘/禁主题 |
| WM_CTLCOLORSTATIC | 合计标签（IDC_SUM_LABEL）返白底刷防旧字重叠；其余透明 |
| WM_CTLCOLORBTN | BS_AUTOCHECKBOX 返白底刷（首版 NULL_BRUSH 曾致复选框整块空白，已修复） |
| WM_ACTIVATE / WM_TIMER | 失焦 5 分钟自动重置 |
| WM_ERASEBKGND | 返回 TRUE（防闪烁，背景统一在 WM_PAINT 画） |

## 九、交互逻辑详解

### 9.1 数量输入与步进

- 输入框子类 `SlotEditProc`：仅接受半角数字 / 退格 / 回车；粘贴时过滤只留数字（最多 2 位）；
- `EM_SETLIMITTEXT(2)`；
- ▲/▼ 步进：范围 0..99 钳制，每次改变后 `UpdatePreview`（刷新合计、二维码数据、按钮状态）。

### 9.2 合计标签

`UpdateTotalLabel()`：`swprintf("入库/上架/盘点合计 %d 件")`，N = 16 格 `atoi` 总和；在 `UpdatePreview` 开头调用。动态 `SetWindowTextW` 必须白底擦旧字（WM_CTLCOLORSTATIC 特判 IDC_SUM_LABEL），否则新旧数字叠印。

### 9.3 两个复选框的显隐与语义

| 当前标签 | 「入库并同时上架」 | 「日结盘点(E)」 | 当前操作码 |
|---|---|---|---|
| 入 库 | 显示 | 隐藏 | `I`（勾选双份时另出 `O`） |
| 上 架 | 隐藏 | 隐藏 | `O` |
| 盘 点 | 隐藏 | 显示 | 未勾选 `C` / 勾选 `E` |

- 点击 → 系统自带勾选态，同步 `g_bothChecked` / `g_eodChecked`（BM_GETCHECK 权威判定，不用 `!` 取反）；
- 勾选 E 后操作码由 C 变 E，需立即 `UpdatePreview`（签名与二维码内容随之变化）；
- 隐藏只影响显示，勾选态保留在变量里；`CurrentOp()` 在盘点标签读 `g_eodChecked ? 'E' : 'C'`；
- DoReset 时两个复选框都 `BM_SETCHECK(BST_UNCHECKED)` 且变量清零。
- **「日结盘点(E)」用状态取反而非回读控件**：`g_eodChecked = !g_eodChecked` 后再 `BM_SETCHECK` 同步控件。系统复选框真实点击时已自动切换，取反结果与之一致；这样同一路径也能被脚本驱动——**跨进程对复选框发 `BM_SETCHECK`/`BM_CLICK` 在本机实测不生效（`WM_SETTEXT` 改控件文字、改窗口标题却都生效）**，靠回读控件判状态的写法在自动化里会一直读到 0，无法验证。

### 9.4 防误操作规则

1. **入库/上架全零禁用**：`IsAllZero()` 判 16 格全 0/空 → `RefreshButtons` 禁用重置/打印；**盘点标签例外**（`canUse = checkTab || !g_allZero`）；
2. **盘点全零二次确认**：C/E 且全零时点打印 → 「全零盘点票确认」弹窗，默认按钮「否」，选否不打印不存档（理由：高价值件卖得慢，全零多为误操作）；
3. **失焦 5 分钟自动清空（重置一切）**：`WM_ACTIVATE(WA_INACTIVE)` 且非模态对话框期间 → `SetTimer(30s)` 轮询，满 5 分钟调 `DoReset(hwnd, false)`：清空 + 取消复选框 + **标签切回「入 库」**；获焦取消计时、保留输入；帮助窗口/打印对话框/全零确认弹窗期间（`g_inDialog=true`）不启动计时；
4. **打印成功自动清空（保留标签）**：`EndDoc` 成功后调 `DoReset(hwnd)`（默认 `keepTab=true`），清空但**不切回入库**；**取消打印对话框不置零**；手动「重置」按钮同样走 `keepTab=true`，保留当前标签。

### 9.5 DoReset（统一重置）

签名 `DoReset(HWND hwnd, bool keepTab = true)`，两条路径共用一个函数、只差标签处理：

| 调用方 | keepTab | 标签行为 | 场景 |
|---|---|---|---|
| `PrintQr` EndDoc 成功后 | `true` | 保留当前标签 | 打完上架票，下一张还是上架 |
| 手动「重置」按钮 | `true` | 保留当前标签 | 手工清空重来 |
| `WM_TIMER` 失焦超时 | `false` | 切回「入 库」 | 放太久没动，重置一切 |

`keepTab=false` 时先做 `g_radioSel = IDC_RADIO_IN` + `TabCtrl_SetCurSel(g_tabOp, 0)`，再走后续步骤（`UpdateChkVisibility()` 依赖 `g_radioSel`，顺序不能反）。

公共步骤：两个复选框取消勾选（`g_bothChecked=false`、`g_eodChecked=false`，再显式 `UpdateChkVisibility()` 让当前标签的复选框按规则显隐）→ 16 框置 "0" → `UpdateTotalLabel()` → `UpdatePreview`。

含义：打完一张上架票，下一张填完数直接还是上架，不必手动切回去，避免打完上架单又跳回入库导致误操作。操作码由 `CurrentOp()` 按 `g_radioSel` 现取，`keepTab=true` 时不改写 `g_radioSel`，所以下一张票的 `I/O/C/E` 自动与当前标签一致。

### 9.6 帮助窗口

非模态（`MhxyQrHelpWnd`，540×440，主窗居中），只读 EDIT 显示 HELP_TEXT；「关闭」`DestroyWindow`；打开期间暂停失焦计时。HELP_TEXT 要点：基本流程、入库并同时上架、**盘点（C/E）**、防误操作规则、二维码数据格式（I/O/C/E）、背景图/横幅自定义提示。

### 9.7 盘点票（C/E）打印口径

- 「盘 点」标签默认打 `C`（中途盘点），勾选「日结盘点(E)」打 `E`；
- 16 格填**实际在售件数**（快照），不是变动量；
- 允许全零，但点打印必弹确认（见 9.4 第 2 条）；
- 打印页标题分别为「中途盘点」「日结盘点」，存档文件名同步；
- 与「入库并同时上架」无关：`dual = (CurrentOp()=='I' && g_bothChecked)`，盘点时恒为单份。

## 十二、已验证边界与工程经验（维护须知）

### 已论证做不通 / 已被否的方案

| 方案 | 结论 |
|---|---|
| 58mm 条形码（Code128） | 模块 <0.19mm 下限，扫不出，已否 |
| 16 组数字压缩（zlib / 位打包） | 数字串压不动 / 膨胀，已否 |
| 互斥按钮样式（蓝底/透明） | 用户"1 和 2 都不用管"，已由系统 Tab 取代 |
| 复选框文字居中（BS_CENTER） | 方块固定最左、仅文字居中，用户否决 → 用文字前 2 半角空格 |
| 命令按钮自绘（BS_OWNERDRAW 白底圆角+投影） | 用户两次否决"不要自绘 / 不要阴影" → 保持系统按钮 BS_PUSHBUTTON |
| 按钮改黑体（SimHei / 禁主题 SetWindowTheme） | 主题化按钮忽略 WM_SETFONT（回读=YaHei UI 400）；禁主题虽可生效但用户"不折腾了"，保持微软雅黑粗体现状 |
| 界面二维码预览 | 已取消（打印/存档逻辑保留） |

### 验证纪律（踩坑记录）

- **跨进程 BM_CLICK 配正确句柄有效**（推翻早前"UIPI 拦截"结论）；BM_GETCHECK 是权威勾选判定；
- **跨进程 `SendMessage` 绝不能传指针**：给控件发 `TCM_GETITEMRECT`（`RECT*`）或伪造 `WM_NOTIFY`（`NMHDR*`）时，指针指向验证脚本进程，目标进程解引用即 `0xc0000005`，崩在 `COMCTL32.dll` 偏移 `0xe710`——本机两次"点盘点标签闪退"实为验证脚本所致，程序本身正常。验证脚本只传标量（`TCM_GETCURSEL`/`BM_GETCHECK`/`BM_CLICK` 安全），点击坐标用 `GetWindowRect(控件) + 4 + 96*idx + 48` 推算；
- **点击前必须还原并确认前台**：`ShowWindow(9)` + `AttachThreadInput` 强制前台 + 断言 `GetForegroundWindow()==窗口`；否则第一次点击只用于激活窗口，控件收不到（曾因此误判"点击无效"）；
- **`TCN_SELCHANGE` 内不动兄弟控件**：只 `PostMessage(WM_APP_TABCHANGED)`，延后到消息队列里再改显隐/刷新（重入加固）；
- 跨进程 `SetWindowText` **不触发** EN_CHANGE；
- **`GetWindowTextW` 在文本为空时一个字符都不写**（2026-11-09 "数量为 10 时二维码异常"的根因之一）：`SlotValue` 原用未初始化的 `wchar_t buf[8]`，空格子会把栈残留读成 `03/05/06` 等随机数字，再经 `WideCharToMultiByte(CP_ACP)` 转成字符拼进内容。已改为 `= {0}` 清零 + 校验 `n <= 0` 直接返回空 + 逐字符只留 `'0'..'9'` 最多 2 位。同批次另加两处加固：`BuildContentFor` 对数量段做 32 位长度兜底（不足补 `0`、超出 `resize`），`DefaultFileNameFor` 切片改 10 位时间 + 操作码；
- **"扫码少一位"不等于"程序少生成一位"**：用户手扫 42 位、存档解码 43 位，两者关系是「删掉内容第 12 个字符后整体左移」——是扫码端丢字符（内容含垃圾时图案失真更易误读），不是程序少拼一位。取证看「保存单据」里的 PNG：文件名本身就是 `OpName_时间戳_数字串`，再用 `PIL.Image.open(...).convert("L")` 转灰度 + `cv2` 解码复核（`cv2.imread` 读不了中文路径，`pyzbar` 缺 DLL 不可用，`detectAndDecode` 返回 3 元组取 `[0]`）；
- **"扫码少一位"要先量码本身能不能被解码器读出**：扫码盒报 42 位、且是开头一位被吃（真实 `13111010…` 扫成 `3111010…`）时，先量存档 PNG 的二维码：`detectAndDecode` 能返回 43 位 → 码是对的，问题在打印浓度/纸面/扫码枪；`detectAndDecode` **直接检测不到**（DECODE_FAIL，连 `pts` 都没有）→ 码本身已密到读不出，必须先把模块放大（见第七章「编码模式」），不要往扫码端找原因。判断模块是否够大：量 `qrbox` 宽 ÷ 单模块像素，29×29 且单模块 ≥10px 才算稳；
- **同一组数字换编码模式前后对比最有说服力**：15:21 的 `13/11/10/10`（字节模式）与 15:29 的同一组数（字母数字模式）留在 `保存单据` 里，前者 DECODE_FAIL、后者 43 位全对，可直接复现验证；
- **"丢的不是开头，而是操作符后第一位"＝输入法吞字符，不是码或程序问题**：扫码盒按键盘协议把字符串打进输入框，中文输入法收到字母 `I/O/C/E` 会进拼音候选态，紧跟其后的第一位数字被当成候选序号吃掉。表现是 43 位变 42 位、缺位固定在操作符之后（如 `…C 13 11 10 10` 扫成 `…C 3 11 10 10`）。判别三步：①同一张纸用手机扫，是完整 43 位；②扫进记事本，也是完整 43 位；③切英文输入法再扫，恢复正常——三条同时成立即锁定输入法，**不要去改二维码、也不要在解析端猜字符补位**（月份 1–9 首字符是 `0`、10–12 月是 `1`，猜错会改坏时间戳）。扫码盒加"前缀字符"对这个现象无效，因为丢位在串中间、不在串首；
- **验证脚本自身会制造假象**：连续多场景跑打印时，若上一个 `#32770` 打印对话框没有完全销毁，`BM_CLICK` 会排队到下个场景，出现"某组莫名变成 06""合计与格子不一致"之类的假阳性。场景切换前必须确认对话框已销毁；另注意程序有"失焦满 5 分钟自动置零"（`WM_ACTIVATE` + `SetTimer` + `WM_TIMER` → `DoReset`），自动化长时间跑动时会被它清掉正在设的值，读到的可能是半程状态；
- **切标签与点重置的顺序**：`DoReset` 已改为**保留当前标签**（不再把 `g_radioSel` 打回入库、也不再 `TabCtrl_SetCurSel` 归零），所以"先切盘点再点重置"不会再被悄悄切回入库，旧版那条顺序约束已失效。但要注意反向影响：脚本若打算"重置后从入库标签开始下一场景"，现在必须**显式切回入库**，否则会沿用一个场景留下的上架/盘点标签；判断标签以 `TCM_GETCURSEL` 为准，判断操作名以合计标签文字（入库合计/上架合计/盘点合计）为准；
- **取消打印对话框不会走 `DoReset`**：`PrintDlgW` 返回 FALSE 时函数直接 `return`，格子保持原样；存档文件在 `PrintDlgW` 之前就已由 `ensureSaved` 写出，所以"取消了还留下 PNG"是正常行为，不要据此判断打印成功；
- `raw.githubusercontent.com` 直连失败，须走 gh-proxy.com；
- `fopen/fprintf` ANSI API 中文路径静默失败，日志须纯 ASCII；
- **不操作用户鼠标键盘**：统一 PowerShell Win32 P/Invoke（FindWindow/GetWindowRect/SetForegroundWindow/ShowWindow(9)）+ System.Drawing CopyFromScreen 截图；
- 控件坐标一律用控件句柄 `GetWindowRect` 屏幕坐标（勿套客户区偏移）；
- 固定像素采样会被窗口移动/遮挡/半透明蒙层误导 → 弃用，以进程内日志 / BM_GETCHECK 为准；
- `TCM_SETCURSEL` 不发 TCN_SELCHANGE（重置回"入库"须显式 ShowWindow 复选框）；
- 跨进程按文字定位复选框：注意文字**带前导空格**（`Like` 通配匹配）；
- **布局微调验证纪律**：控件坐标一律 `EnumChildWindows + GetWindowRect + ClientToScreen`（屏幕坐标减客户区原点）；截图统一 Python P/Invoke `capture_ui.py`（FindWindow→ShowWindow(9)→SetForegroundWindow→PIL ImageGrab，不操作用户鼠标键盘）；
- **背景玻璃台强约束**：dy=52 固定（台面 232-356），用户两次强调"背景图片不要动"——移动按钮/合计等控件时背景一律不动；
- **Tab 标签间距/居中**：标签间无原生间隔概念，靠 `TCM_SETITEMSIZE` 加宽 + `TCS_CENTER`（0x0800，MinGW 头文件无此常量定义须写数值）让文字居中拉开；标签文字曾"入库 (I)"，用户改为「入 库」「上 架」；

### 遗留说明

- 相同数据重复打印会生成多张 PNG（时间戳不同）——用户已接受"打印成功之后重置"设计；
- 界面二维码预览已取消，全零灰度提示随之消失，但全零仍经 RefreshButtons 禁用按钮；
- 打印页 `print_page.hpp` 为定稿，改动前须先与用户确认版式。
