# 梦幻西游灵饰经营管理 · 操作规范

本文件是灵饰台账系统的**标准作业规范（SOP）**，涵盖业务口径、扫码动作、库存双轨、回款、日报、撤票与备份。开发与日常执行一律以本文件为准；历史演进细节见 `工作流程指导.md`。

---

## 一、角色与口径

- 经营角色：广东四区白云山区灵饰商人，品类 60/80/100/120 级，戒指 / 耳饰 / 手镯 / 佩饰 共 16 款。
- 记账单位：金额一律「万」梦幻币（1 万梦幻币 = 10,000 两），人民币按当日汇率折算。
- 汇率口径：实时从接口取价，禁止本地硬编码；四行显示（3000 万≈¥X / 1 万≈¥X / 1 元≈X 万金币 / 1 点卡≈X 万金币）。
- 汇报口径：先结论后细节，即时直接给数字；所有汇总必须用工具计算，禁止口算；表格不折叠。

---

## 二、业务日分界（核心规则）

1. **E 票日结是唯一跨天分界**，不按自然日 0 点、也不按 22 点整点自动跳天。
2. 未扫 E 票之前，不论几点（哪怕到凌晨），所有 I/O/C 操作与回款都算**当天**。
3. E 票本身是当天最后一笔，通常在 22:00–22:15 完成日结。
4. E 票之后新扫的票、新登的回款，全部归**次日**。
5. 跨天更正只改确属前一天的单条记录，E 票及其后记录不动，禁止批量改日期。

---

## 三、品类主表与价格

- 品类元数据统一存 SQLite `category` 主表（`idx, name, part, level`），扫码解析、日报、`/data` 下发、前端价格表全部读主表。
- `idx` 槽位顺序是**扫码契约**，1–16 固定不可重排：60 级戒/耳/镯/佩 → 80 级戒/耳/镯/佩 → 100 级戒/耳/镯/佩 → 120 级戒/耳/镯/佩。
- 售价、成本存 `price_history` / `cost_history`，**一律以最新生效记录为准**；配置文件里的价格表只是历史快照，不作数据源。
- 调价硬约束：先列出新旧价格对比清单，经确认后写库；同步更新网页、报表、销售明细计算口径。调价日按时间点分段，历史销售不回溯改价。

## 四、二维码扫码契约

### 4.1 文本结构

共 **43 位**：`MMDDHHMMSS`（10 位时间戳）+ 操作符（1 位 I/O/C/E）+ 32 位数字（每两位一个品类数量，16 个品类按主表顺序）。

### 4.2 操作符

| 操作符 | 含义 | 完成动作 |
|--------|------|----------|
| I | 入库 | 库存增加，展示入库前后库存对比 |
| O | 上架 | 库存减少、在售增加，展示上架前后在售对比 |
| C | 中途核查 | 实盘在售 vs 账面在售，差额即销售 |
| E | 日结盘点 | 全天累计核对，生成日报并结转次日 |

### 4.3 扫码前置与自检

- 扫码前**必须切英文输入法**（中文输入法会吞掉操作符后首位数字，导致数量错位）。
- 长度不足 43 位（如 42 位残缺串）一律重扫，不猜测补全。
- 扫完先核对弹窗总件数，明显异常（几十上百件）直接撤销，不确认入账。
- 全零票不开放，按无效票处理。
- 连扫同数量 I+O（新货直接上架）时库存净效果不变，只更新在售矩阵，两票分别登记。

## 五、双轨库存逻辑

库存（storage）与在售（onsale）**独立维护**：

- 入库 I：只加库存，不动在售。
- 上架 O：库存减 N、在售加 N，两条流水都要写（入库明细同步写负数量）。
- 销售：由「应有在售 − 实际在售」反推，不单独登记。
- 中途核查 C / 日结 E：以实盘重设在售，差额逐品类写入销售明细。

盘点差异出现一正一负、总量不变时，先怀疑登记品类串号，列对冲清单让用户复核实物后再落库，不按盘亏盘盈分别调账。

## 六、四类操作标准动作

### 6.1 入库（I）

1. 解析扫码文本（`items` 字段，不取 `rows`）。
2. 写扫码日志 1 行（A 账面日期 / B 完整时间 / C 操作符 / D 43 位原文 / E 明细串 / F 数量）。
3. 非零品类逐条写入库明细。
4. 更新库存矩阵，展示前后对比。

### 6.2 上架（O）

1. 解析扫码文本。
2. **先试算**：对应库存 − 上架量，出现负数立即停止并提问，不硬落表。
3. 库存够则写日志、写上架明细，并在入库明细同步写负数量。
4. 库存矩阵减、在售矩阵加，展示前后对比。

### 6.3 中途核查（C）

1. 解析实盘在售数。
2. 反推销售：账面在售 − 实盘 = 各品类销量。
3. 写日志，有销售的品类逐条写销售明细（含单价、金额、毛利率、毛利润）。
4. 在售矩阵更新为实盘值，同步面板 today/cash，展示销售明细并连带回款情况。

### 6.4 日结盘点（E）

1. 解析并写日志，反推全天累计销售。
2. 生成当日日报（16 品类固定顺序，卖空品类照列显示 0 或「-」）。
3. 汇总总销量、销售额、回款、点卡回款、未回款、汇率折算。
4. 报表数据必须从销售明细逐行 SUM，禁止凭记忆或估算。
5. 日结后当日数据清零准备次日，历史流水不清空，按天累积。
6. 若 E 盘值与当日最后一张 C 完全一致，无新增销售，直接标记 `settled=true`。

## 七、回款

- 顺序硬约束：**先盘点（C/E）算出销售额，再登记回款**，否则未回款会算负数。
- 未回款 = 累计销售额 − 累计正常回款；超出当日销售额的部分统一记「点卡回款」，不冲减应收。
- 回款登记带日期控件，默认跟随当前业务日；补前一天的款项手动改选归属日；实际发生时刻与归属日分开记录。
- 每笔回款写入 cash_log 并同步面板 `cash.json` 的 history 数组（time / 万）。

---

## 八、日报（交老板版，固定格式）

列结构固定：品类 / 销量(件) / 销售额(万) / 成本(万) / 毛利润(万) / 毛利率。

- 16 品类顺序固定，零销量品类显示「-」。
- 毛利率保留 1 位小数；底部汇总回款总额、未回款、人民币折算。
- A4 横向打印、适应页宽、表头加粗。
- 网页支持日报/周报导出 CSV（UTF-8 带 BOM，文件名带日期），列：品类/等级/部位/件数/金额/成本/毛利 + 合计行；周报：日期/销售件数/销售金额/毛利 + 累计行。
- 等级显示统一取后端 `level` 文本，前端不再二次拼「级」。

## 九、撤票（回滚）SOP

1. 定位目标票（业务日 + 时间 + 操作符 + 明细串），盘点票连带其 SUMMARY 汇总条。
2. **先备份数据库**：备份为 `mhxy.db.bak-rollback-YYYYMMDD-HHmmss`，确认落盘。
3. 反推应有状态：盘点票按「上一张盘点实盘 + 其后所有 O 增量」反推在售；I/O 按流水反向推。
4. 列撤销清单经用户确认后，事务内执行：删明细与该票、反向恢复矩阵。
5. 回读验算：件数/金额闭合、库存与在售合计、流水条数、前端 `/data` 显示一致。

| 票型 | 明细 | 库存 | 在售 |
|------|------|------|------|
| I 入库 | in_detail 正数量 | 按入库量减回 | 不动 |
| O 上架 | out_detail + in_detail 负数量 | 按上架量加回 | 按上架量减回 |
| C/E 盘点 | sale_detail 本轮差额 + 主票 + SUMMARY | 不动 | 按上一张盘点 + 其后 O 增量恢复 |
| 回款 | cash_log 记录 | 不动 | 不动 |

- 撤 E 票后必须明确提示「当天尚未日结」，需重新扫 E 票定稿，旧汇总条一并删除。
- 网页撤票一期仅开放 I / O：只读预检 → 二次确认 → 自动备份 → 事务冲销 → 回读验算；撤后会出现负库存/负在售则拒绝；C/E 仍由助手核对库表处理。

## 十、系统组件与启动

| 组件 | 说明 |
|------|------|
| `app_server.py` | 打包源码（本地 HTTP 服务 + SQLite 读写 + 扫码解析） |
| `server.py` | 历史回退快照，不被任何入口调用 |
| `工作台.html` | 前端单页，3 秒/手动刷新，所有经营数据入口 |
| `mhxy.db` | SQLite 台账库（不发版、不入库仓库） |
| `启动工作台-exe.bat` | 唯一启动入口（杀旧进程 → 起服务 → 开浏览器） |
| `汇率悬浮窗.ps1` | 纯汇率条，贴边隐藏，不读业务 json |

- 访问工作台一律走启动脚本，不在浏览器地址栏手敲 localhost（HSTS 会强制跳 HTTPS）。
- 改 `app_server.py` 后：`py_compile` 校验 → PyInstaller 重新打包 → 覆盖根目录 exe → 重启；打包顺序必须「先杀进程再覆盖」，否则文件被占用。
- 子进程调用不得依赖 PATH 裸 python，取服务端同目录 `python.exe`（pythonw 无 stdout，JSON 会被吞成空错误）。

## 十一、数据面板四文件

`stock.json`（在售）、`storage.json`（库存）、`today.json`（当日：含 provisional 截止时间/销量/额/人民币）、`cash.json`（回款 history）。每次飞书/库内落表后同步这四份，保证工作台与面板实时显示；盘点后立即更新并重启面板。

---

## 十二、备份、自检与复盘

- 每日 00:30 自动打包项目为 zip 上传云盘；重大操作（撤票、盘库校正、勘误）前必须手动备份数据库。
- 每日 8:00 开工自检：通读本规范，扫码核对 16 组对应表，追加前读尾行，上架前试算，入库/上架后展示对比表，核查日结连带回款。
- 每日 23:00 复盘：回顾当天操作，固化新规范，经确认后更新本文档，次日按新规执行。

---

## 十三、常见错误处理

| 场景 | 处理 |
|------|------|
| 口算/汇总出错 | 一律用工具计算，禁止口算 |
| 回款算错 | 点卡回款不抵扣销售额，只有正常回款冲应收 |
| 库存不足上架 | 先试算并提问，不硬落表 |
| 撤回入库 | 检查后续上架是否依赖该批，避免库存变负 |
| 扫码长度不对 | 提示缺位并重扫，不猜补 |
| 追加写入错位 | 先读最后一行行号再追加，禁止凭记忆累加 |
| 扫码返回空错误 | 双击桌面启动脚本重启服务；排查 err/error 字段同名问题 |
| 前端显示旧数据 | 一律读接口/库内值，禁止在 HTML 写死历史数字 |
