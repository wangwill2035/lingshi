# 《入库上架二维码打印工具》开发回顾与经验总结

版本：1.0（2026-11-04 布局定稿后）
用途：为后续进一步开发打下基础，减少无效沟通与返工

---

## 一、开发历程回顾（时间线）

| 阶段 | 内容 | 关键结论 |
|---|---|---|
| 1. 需求与契约定稿 | 16 格灵饰数量、入库/上架切换、58/80mm 热敏打印、自动存 PNG；数据契约 = 10 位时间戳 + I/O + 16×2 数字直连；名称表（60-120 级 16 件，相思染定稿）；7 条交互契约 | **契约先行是最大功臣**：二维码可复现、可离线验证，全程无结构性返工 |
| 2. 初版实现 | 编译管线（windres + g++）、qrcodegen 引入、打印/存档实现、离线回归 test_print/test_save | 编译/分发管线一次成型 |
| 3. 控件体系确立 | 单选/复选框/命令按钮曾走自绘 → 反复出问题（勾选去不掉、透明灰底）→ 全部改系统标准控件重写 | **系统控件优先**原则确立 |
| 4. 打印版式调优 | 58mm qrRatio 0.90→0.96（0.90 扫不出）、80mm 0.72；标题/双线/表头/数据行逐行确认 | 打印参数必须实测验证，不能凭理论 |
| 5. 布局微调期（耗时最长） | 窗口 404→429（客户区 375→400）；格网 132→126；合计 280→296；按钮 312→346（六次往返）；间距 12→16→26px；Tab 82→96 + 居中 + 文字「入 库」「上 架」；横幅全宽固定 58；玻璃台对位 dy=52 | 布局是"感觉"驱动，最易无效沟通；须一次只改一个维度 |
| 6. 图标嵌入 | image_gen 生成主图 → make_ico.py 转多尺寸 ICO → app.rc 资源嵌入 → 标题栏/任务栏/资源管理器三处验证 | 图标资源化嵌入方案可复用 |
| 7. 按钮字体探索（无果） | 加粗→"没看到效果"→黑体→禁主题→用户"不折腾了" | 主题化按钮忽略 WM_SETFONT，应最先用 WM_GETFONT 回读诊断 |
| 8. 技术手册 | 12 章 + 图标补记 + 布局同步 v1.1.0 | 手册与源码/EXE 三者同步维护 |

## 二、做得好的（可复用资产）

1. **数据契约与名称表先定稿**——二维码内容格式、DataSignature、16 件名称全部先行锁定，后续所有功能/打印/存档都建立其上，没有结构性返工。
2. **打印/存档离线回归**——test_print.exe / test_save.exe 用固定内嵌串渲染 PNG，打印页版式任何改动都可离线验证，不依赖真机打印。
3. **验证纪律成型**（已沉淀到手册十二章）：
   - 控件坐标：`EnumChildWindows + GetWindowRect + ClientToScreen`（不套客户区估算）；
   - 截图：`capture_ui.py`（FindWindow → ShowWindow(9) → SetForegroundWindow → PIL ImageGrab，不操作用户鼠标键盘）；
   - 勾选/状态判定：跨进程 `BM_GETCHECK` 权威；
   - 文件替换：停进程 → 替换 → 哈希核对 → 重启（GDI+ 锁定）。
4. **系统控件优先**——交互稳定性大幅提升，自绘仅保留无系统替代的 ▲/▼ 步进钮。
5. **图标资源化嵌入**——app.ico 多尺寸 + manifest，三处显示，分发零附加文件。
6. **技术手册"已验证边界/踩坑记录"**——12 章把"做不通的/被否的/踩过的"全部留痕，后人不再重复试错。

## 三、踩过的坑与教训（避免重蹈）

| 坑 | 表象 | 根因 | 教训 |
|---|---|---|---|
| 自绘控件反复返工 | 复选框勾选去不掉、单选透明灰底 | 自绘复杂状态处理易错 | 能用系统控件就不用自绘；交互类控件尤其 |
| 布局数值多轮往返 | 按钮 Y 六次调整（312→318→326→346→356→346） | 无量化目标，"感觉"驱动 | 改前先问目标间距/对齐关系；一次只改一个维度；给用户看前后对比 |
| 按钮字体探索无果 | 加粗"没看到效果"→黑体→禁主题→放弃 | 未先诊断就改；主题化按钮忽略 WM_SETFONT | 效果类问题先验证（WM_GETFONT 回读/截图）再改；发现被忽略先查机制 |
| 附带改动惹恼用户 | "按钮下移30px"顺带改背景 dy=82，用户两次强调"背景不要动" | 超出点名范围 | 微调请求严格只改点名项，装饰层默认不动 |
| 像素采样误导 | 固定像素采样被窗口移动/半透明蒙层误导出错误结论 | 验证方法选错 | 先选对验证方法（句柄坐标/权威消息），再下结论 |
| 无效沟通 | "合适""漂亮"等描述与数值期望落差 | 双方没有量化语言 | 用"多少 px / 对齐关系 / 参考截图"对齐，避免模糊词 |

## 四、协作与沟通改进建议（减少无效沟通）

1. **沿用"需求讨论→逻辑定稿→再改码"**：涉及功能/行为变更先逐点讨论、我复述要点、你确认后再实现。
2. **微调类请求**：一次一个点；动手前我复述"本次只改 X，其余不动"，你确认。
3. **涉及多项改动**：先列改动清单（要改的/不动的）让你拍板，再动手。
4. **效果类反馈**（字体/颜色/间距"没效果/不合适"）：我应先给出诊断（回读/截图对比）再改，不盲目试。
5. **量化语言**：布局对齐尽量给"间距 X px""与 Y 对齐""参考截图标注"；我用控件实测坐标回报。
6. **布局常量集中管理**：main.cpp 顶部常量表是唯一权威，改一处同步手册第八章。

## 五、后续开发"勿改/需谨慎"清单

- **数据契约**（10 位时间戳 + I/O + 16×2 直连、DataSignature）——改必须同步 main.cpp + test_print/test_save 内嵌串；
- **名称表**（枫华戒…相思染 16 件）——勿拼错；
- **print_page.hpp**——打印版式定稿，改动前先与用户确认；
- **背景玻璃台 dy=52**——用户两次强调"背景图片不要动"，装饰层强约束；
- **命令按钮**——系统按钮 + 微软雅黑粗体现状，勿再自绘/禁主题/加阴影（用户明确否决）；
- **EXE 名不含"打印"**；编译先停旧实例防 ld Permission denied。
